# Notion CMS: 글 하나로 연결 검증하기

이 단계는 글 한 개만 수동으로 동기화하는 로컬 검증입니다. 자동 배포와 기존 글 이전은
연결하지 않습니다. Node.js 22 이상에서 실행합니다.

## 현재 검증에 사용한 Notion 글

- 데이터베이스: 기존 `Myblog_CMS`
- [블로그 CMS 연결 테스트](https://www.notion.so/41712f7c14b78120b615d5d33a83f9bc)
- 기존 `Status` 선택 속성을 그대로 사용합니다. `Published`만 발행 대상으로 처리하고,
  `Draft`·빈 값·알 수 없는 상태는 초안으로 처리합니다. `Date` 속성도 읽습니다.
- 체크박스와 Status를 함께 사용하는 경우 서로 모순되면 동기화를 중단합니다.

Notion 플러그인으로 실제 글과 사진을 읽어 검증할 수 있습니다. 이 방법은 에이전트가
그때그때 가져온 응답을 동기화하는 수동 경로입니다. 독립 실행·자동 동기화용
`notion:sync` 명령은 아래의 내부 연결 API 키 설정이 별도로 필요합니다.

플러그인에서 `include_file_urls: true`로 처음 읽은 응답과 다시 읽어 수정 시각을 확인한
응답을 `.notion-test/evidence/`에 저장한 뒤 다음 도구로 가져옵니다.

```sh
node scripts/notion-connector-test.js <처음읽은응답.json> <다시읽은응답.json>
```

이 도구는 실제 응답의 속성·본문·사진 다운로드 URL을 기존 동기화 함수에 전달합니다.
서명 URL은 원고에 남기지 않으며, 원본 응답은 Git에서 제외된 로컬 검증 폴더에만 둡니다.
URL이 만료되면 Notion에서 다시 읽어야 합니다.

## 1. Notion 테스트 글과 접근 권한

1. Notion에 테스트용 데이터베이스를 만들고 글 한 개를 추가합니다.
2. 제목 외에 `초안`이라는 **체크박스** 속성을 추가하고 체크합니다.
   `Draft` 또는 `draft`도 지원합니다. 속성이 없으면 안전하게 초안으로 취급합니다.
   기존 `Myblog_CMS`는 체크박스 대신 `Status: Draft`를 사용하면 됩니다.
3. 본문에는 짧은 문장과 PNG/JPEG/WebP/GIF 사진 한 장을 직접 업로드합니다.
   이번 검증은 20MB 이하 사진, 일반 본문·제목·목록·코드 블록을 대상으로 합니다.
   Notion 전용 색상·토글·임베드 등은 오류를 표시하고 이전 정상 파일을 유지합니다.
4. Notion 개발자 설정에서 내부 연결을 만들고 **콘텐츠 읽기** 권한을 설정합니다.
5. 테스트 데이터베이스의 연결 메뉴에서 해당 연결에 접근 권한을 줍니다.
   개인 메모 전체를 공유할 필요는 없습니다.
6. 데이터베이스 주소가 아닌 **글 페이지 링크**를 복사합니다.

설정 안내: [Notion 내부 연결](https://developers.notion.com/guides/connections-and-tokens/internal-connections).
이 채팅의 Notion 플러그인 연결과 블로그 동기화에 쓰는 API 키는 별개입니다.

## 2. 키는 로컬 파일에만 입력

프로젝트 루트의 `.env.notion`을 다음처럼 설정합니다. 파일은 Git에서 제외됩니다.

```dotenv
NOTION_API_KEY=실제_내부_연결_키
NOTION_TEST_PAGE_ID=https://www.notion.so/테스트글의페이지주소
```

키를 채팅·소스 코드·`GATSBY_` 환경 변수에 넣지 않습니다. SDK 설치는 필요하지 않습니다.
동기화 명령이 실행될 때마다 이 파일을 직접 읽고, Notion 공식 HTTP API에 요청합니다.

## 3. 연결 → 사진 표시 → 수정 반영 → 초안 제외

```sh
npm run notion:check
npm run notion:sync
```

`notion:check`는 키와 페이지 읽기 권한을 확인합니다. 401(키), 403(권한),
404(페이지 ID 또는 공유 권한)를 구분해 알려줍니다.
`notion:sync`는 본문과 사진을 `.notion-test/contents/`에 저장합니다.
사진은 파일 내용의 해시로 저장하고 Markdown에서 로컬 파일을 참조합니다.
Notion 이미지의 만료되는 주소를 그대로 사용하지 않습니다.

기존 개발 서버를 종료하고 실행합니다.

```sh
npm run develop:notion
```

`http://127.0.0.1:8000/notion-cms-test/`에서 제목·본문·사진과 초안 표시를 확인합니다.
Notion에서 문장을 고치거나 사진을 바꾼 뒤 `npm run notion:sync`를 다시 실행하면
같은 주소에 수정 내용이 반영됩니다. 현재 단계의 수정 반영은 수동 동기화입니다.

`초안` 체크 여부를 변경한 뒤 매번 동기화하고 다음을 확인합니다.

| Notion 상태 | `develop:notion` | `build:notion-test` |
| --- | --- | --- |
| 초안 체크 또는 속성 없음 | 초안으로 표시, 사진 확인 가능 | 글·홈 목록·이전/다음 글에서 제외 |
| 초안 체크 해제 | 발행된 글로 표시 | 글과 목록에 포함 |

```sh
npm run build:notion-test
```

이 빌드는 로컬 테스트 콘텐츠를 명시적으로 포함하는 검증용 빌드입니다. 배포하지 않습니다.
일반 `npm run build`는 `.notion-test`를 읽지 않으므로 체크 해제한 테스트 글도 포함하지 않습니다.
초안의 사진 자체를 비공개로 제공하는 기능은 아닙니다. 민감하지 않은 테스트 사진을 사용합니다.

## 보존 및 실패 처리

- 기존 `contents/` 원고는 수정하지 않습니다.
- 테스트 글 주소는 `/notion-cms-test/`로 고정하므로 제목 변경으로 주소가 바뀌지 않습니다.
- 본문 누락·지원하지 않는 서식·사진 다운로드 실패·동기화 중 편집을 감지하면 이전 원고를 유지합니다.
- `.notion-test/report.json`에서 마지막 정상 동기화 시각, 초안 상태, 사진 수를 확인합니다.
- 원고·사진·실행 결과는 Git에서 제외되며, 키와 사진 서명 URL은 오류 로그에 출력하지 않습니다.
- 실패한 동기화 이후에는 `report.json`의 마지막 성공 시각을 확인합니다.

자동 검사: `npm run test:notion`. 이 검사는 가짜 API 응답과 실제 이미지 파일을 사용한
로컬 회귀 검사입니다. 실제 Notion 권한·업로드·수정 반영 검증은 위 절차로 별도 수행합니다.
