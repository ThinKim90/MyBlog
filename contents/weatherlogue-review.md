# Weatherlogue 제작기
**오늘 날씨에 어울리는 고전문학 한 문장**

날씨 앱은 기온과 강수 확률을 알려 준다. **Weatherlogue**는 거기에 한 줄을 더한다. 비 오는 날엔 비에 어울리는 시 한 구절, 눈 오는 밤엔 눈 내리는 밤의 문장. **오늘 날씨에 어울리는 한국 고전문학 문장**을 보여 주는 감성 날씨 앱이다.

핵심은 알고리즘이 문장을 지어내는 게 아니라 **사람이 직접 고른 문장**을 날씨에 맞춰 보여 준다는 것.

> ✍️ 이 앱을 떠올린 계기

> 아직 만들고 있는 앱이라, 이 글은 중간 기록이다.

## 1. 기획부터 단단하게

이번에는 코드보다 **기획 문서(브리프)** 를 먼저 단단하게 썼다. 태그 체계, 날씨 API 매핑, 매칭 알고리즘, DB 구조까지 다 정해 두고, AI에게는 "이 문서를 기준으로" 만들라고 했다. 버전도 v2까지 올리며 확정했다.

파발마나 이전 프로젝트에서 배운 것처럼, **기준 문서가 있어야 AI가 엉뚱한 걸 만들지 않는다.**

---

## 2. 저작권: 1955년 이전에 돌아가신 작가

고전문학이라도 아무 문장이나 쓸 수 있는 건 아니다. 한국은 **작가 사망 후 70년**이 지나야 저작권이 풀린다(퍼블릭 도메인).

- 2026년 기준 **1955년 이전에 돌아가신 작가**의 작품만 쓴다
- 문장은 한국저작권위원회 **공유마당**에서 이미 검증된 목록을 우선 쓴다
- 저작권과 별개로, 친일 행적 등 역사적 논란이 있는 작가는 신중하게 다룬다

예를 들어 김소월의 「산유화」 같은 작품. 나중에 미국으로 넓힐 때는 Project Gutenberg의 영문 퍼블릭 도메인 텍스트를 쓸 계획이다.

> ✍️ 문장을 고르면서 다시 읽게 된 작품 / 가장 좋아하는 문장

---

## 3. 날씨를 태그로 바꾸기

기상청 단기예보 API는 하늘 상태, 강수 형태, 기온 같은 **숫자**만 준다. 이걸 문장에 붙일 수 있는 **날씨 태그**로 바꾸는 규칙을 직접 정했다.

| 태그 | 규칙 |
|---|---|
| 맑음 / 구름많음 / 흐림 | 하늘 상태 |
| 비 / 비눈 / 눈 / 소나기 | 강수 형태 |
| 폭염 | 최고기온 33°C 이상 |
| 한파 | 최저기온 -12°C 이하 |
| 강풍 | 풍속 14m/s 이상 |

여러 조건이 겹치면 **강수 → 폭염·한파 → 강풍 → 하늘 상태** 순으로 하나만 고른다. 기준값은 나중에 조정할 수 있게 상수로 빼 뒀다.

---

## 4. 어떤 문장을 고를까: 매칭 규칙

문장마다 태그를 붙인다.

- **날씨** (필수): 맑음, 비, 눈…
- **감정** (1~2개): 그리움, 위로, 설렘, 고독, 평온…
- **계절**, **시간대** (선택): 없으면 언제든 어울린다는 뜻

고르는 순서는 이렇다.

1. 오늘 날씨 태그가 맞는 문장만 남긴다
2. 계절·시간대가 **딱 맞으면 가산점**, 정반대(여름에 한겨울 문장)면 **제외**, 바로 옆 계절·시간대는 통과
3. **최근 3일 안에 본 문장은 뒤로** 미룬다
4. 날짜·시간대·날씨를 시드로 써서 **같은 조건이면 늘 같은 문장**이 나오게 한다. 그래야 앱과 홈 화면 위젯이 같은 문장을 보여 준다
5. 그래도 후보가 없으면 계절과 상관없는 문장 중에서 고른다. 빈 화면은 없다

## 5. 로그인 없는 앱

MVP에는 **회원가입이 없다.** 저장한 문장과 본 기록은 휴대폰 안에만 두고, 유료 테마는 앱스토어 계정으로 복원하면 충분하다. 계정은 기기 간 동기화가 필요해지는 다음 버전에서, 그것도 선택 사항으로 넣을 생각이다.

수익은 **테마 팩**이다. 문장은 그대로 두고 색·글꼴·일러스트만 바뀌는 스킨이라 저작권 문제도 없다. 기본 무료 테마 하나에 유료 테마 한두 개로 시작한다.

## 💡 지금까지 배운 것

1. **문서가 먼저, 코드는 나중.** 규칙을 다 정해 두니 AI와 일하기가 훨씬 편했다.
2. **퍼블릭 도메인에도 규칙이 있다.** 고전이라고 다 쓸 수 있는 게 아니다.
3. **"랜덤"도 설계해야 한다.** 같은 조건엔 같은 문장, 최근 본 건 뒤로.

> ✍️ 출시까지 남은 일 / 언제쯤 낼 계획인지
